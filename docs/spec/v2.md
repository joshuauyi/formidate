# Formidate v2 — Design Spec

Status: **implemented**, unreleased (v2). This document is the contract the code, tests and docs follow.

## 1. Goals

1. **Little to no boilerplate.** A plain HTML form with native constraint attributes
   (`required`, `type="email"`, `minlength`, …) must validate with one line:
   `createForm().bind('#signup')`.
2. **Framework independent.** The core knows nothing about any UI framework. It works with plain
   DOM, and exposes a store contract (`subscribe` + `getState`) that React
   (`useSyncExternalStore`), Svelte (store contract) and Vue (`shallowRef`) consume directly.
   A tiny React hook ships as a subpath; other frameworks need ~5 lines (documented).
3. **Lightweight.** Zero runtime dependencies. Core budget **≤ 9 kB minified + brotli** (enforced by
   `size-limit` in CI).
4. **Type-safe for real.** Field names, values and submitted output are inferred from the field
   map, including schema output types.
5. **Standards first.** [Standard Schema v1](https://standardschema.dev) for external schemas
   (Zod, Valibot, Yup, ArkType, Effect Schema, …), the HTML Constraint Validation attributes as a rule
   source, and WAI-ARIA (`aria-invalid`, `aria-describedby`) for accessible errors.

### Non-goals

- Rendering UI components, controlled-input state management, field arrays APIs, wizards.
- Coercion/transforms in the DSL — use a schema (`z.coerce.number()`) when you need typed output.
- File objects. File inputs participate as their string value only.

## 2. Prior art / standards referenced

| Source                                                                 | What we took                                                                                                                                                                 |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HTML Constraint Validation (WHATWG)                                    | Attribute names & semantics (`required`, `minlength`, `maxlength`, `min`, `max`, `pattern`, `type`), `novalidate` when a library owns the UI, `form.elements`, `reset` event |
| WAI-ARIA APG / WCAG 3.3.1 (Error Identification)                       | `aria-invalid="true"` only after the user interacted, error text linked with `aria-describedby`, focus the first invalid field on submit                                     |
| Standard Schema v1                                                     | `~standard.validate`, issues with `path`, `InferInput`/`InferOutput`; the interface is vendored as types (spec recommendation), no dependency                                |
| React Hook Form                                                        | uncontrolled-first (DOM is the input), `handleSubmit`, focus first error, `dirty` = differs from default, `submitCount`                                                      |
| TanStack Form / Final Form                                             | framework-agnostic store with `subscribe`; debounced async validators with `AbortSignal`                                                                                     |
| Zod / Valibot builders                                                 | immutable chainable builders, so shared field definitions are safe to reuse                                                                                                  |
| Svelte store contract                                                  | `subscribe(fn)` calls `fn` immediately and returns an unsubscribe function → a `Form` _is_ a Svelte store                                                                    |
| npm packaging (publint, arethetypeswrong, Node ≥ 20.19 `require(esm)`) | ESM-only `exports` map with `types` first, `sideEffects: false`, no global side effects in module code, provenance via trusted publishing                                    |

## 3. Public API

```ts
import { createForm, field, configure } from 'formidate';
import { useForm } from 'formidate/react';
```

Named exports only (no default export — default + CJS interop is the #1 source of
`require('x').default` bugs). The CDN build exposes the same names on `window.Formidate`.

### 3.1 `field(defaultValue?)` → `Field<string | null, string | null>`

Immutable chainable builder: **every method returns a new `Field`**. Type parameters are
`Field<Value, Output>` — `Value` is what the control holds, `Output` is what `handleSubmit`
delivers when valid.

Empty values (`null`, `''`, `[]`) pass every rule except `required` / `minItems`. Built-in rules accept the same strings as their Zod 4 equivalents (`src/zod-parity.test.ts`); deliberate differences: blank = empty, no hex numbers, and lenient ISO date-time separators. All rules take an
optional **message as the last argument**. Rules with several knobs take an options object.

| Group       | Methods                                                                                                                                                                                                                                                           |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Presence    | `required(msg?)` — narrows `Output` to non-null                                                                                                                                                                                                                   |
| Strings     | `email(msg?)` / `email({ allowLocal?, multiple? }, msg?)` (like `z.email()`), `url(opts?: { protocols?, allowLocal? }, msg?)` (like `z.httpUrl()`; `[]` = any scheme), `pattern(re: RegExp, msg?)`, `length(n, msg?)`, `minLength(n, msg?)`, `maxLength(n, msg?)` |
| Numbers     | `number(msg?)` (strict: `Number(v)` must be finite), `integer(msg?)`, `min(n, msg?)`, `max(n, msg?)` (inclusive, like HTML), `greaterThan(n, msg?)`, `lessThan(n, msg?)` (exclusive), `multipleOf(n, msg?)`                                                       |
| Dates       | `date(msg?)`, `minDate(d, msg?)`, `maxDate(d, msg?)` (inclusive)                                                                                                                                                                                                  |
| Choice      | `oneOf(values, msg?)`, `notOneOf(values, msg?)`                                                                                                                                                                                                                   |
| Arrays      | `array(defaults?)` → `Field<string[], string[]>`; `minItems(n, msg?)`, `maxItems(n, msg?)`. String/number/date rules apply **per element**.                                                                                                                       |
| Cross-field | `sameAs(otherName, msg?)`                                                                                                                                                                                                                                         |
| Custom      | `custom((value, { values, name }) => string \| null \| undefined)` — return a message to fail. Stackable. Runs on empty values too (for conditional-required).                                                                                                    |
| Async       | `async((value, { values, name, signal }) => Promise<string \| null \| undefined>, { debounce?: ms })` — stackable, first error wins, runs **only when all sync rules pass and the value is non-empty**, stale runs are aborted via `signal`.                      |
| Schema      | `schema(standardSchema)` → validates alongside any chained rules (HTML-attribute rules are not added); `Output` becomes the schema output                                                                                                                         |
| Label       | `label(text)` — used as `{label}` in messages                                                                                                                                                                                                                     |

A raw Standard Schema may be used in place of a `Field` in `createForm({...})`.

DSL string rules apply to string values (and string elements of arrays). Object values (from
structured names) are only checked as a whole by `required`, `custom`, `async`, `sameAs` and schemas.

### 3.2 Messages

`Message = string | ((ctx: MessageContext) => string)`. Strings are templates: `{label}`, `{name}`,
`{value}` and rule params (`{min}`, `{max}`, `{length}`, `{values}`, `{target}`) are interpolated.

Defaults are full sentences using `{label}`, e.g. `"{label} is required"`,
`"{label} must be at least {min} characters"`. The label resolves to: `.label()` → the bound
input's `<label>` text / `aria-labelledby` text / `aria-label`, or for a choice group the `<legend>` /
`role="group"|"radiogroup"` container's name (read on bind regardless of `html`) →
`fallbackLabel` (`"This field"`). `sameAs` uses the target's label, else its name, for `{target}`.
An async rule that throws produces the `async` message (`"{label} could not be verified"`).

Override per form (`createForm(fields, { messages })`) or globally (`configure({ messages })`),
keyed by rule name — this is the i18n hook.

### 3.3 `createForm(fields?, options?)` → `Form<F>`

```ts
interface FormOptions {
  messages?: Partial<Messages>;
  fallbackLabel?: string; // default "This field"
  html?: boolean; // default true — infer rules + controls from the DOM on bind
  aria?: boolean; // default true — aria-invalid, aria-describedby, [data-formidate-error]
  focusOnError?: boolean; // default true — focus first invalid input on failed submit
}
```

`configure(options)` sets global defaults for all of the above.

#### State (all read-only, immutable snapshots)

```ts
form.getState(): FormState<F>        // same reference until the next change
form.values / controls / valid / invalid / pending / dirty / touched / submitting / submitCount

interface ControlState<V> {
  name: string; label: string; value: V;
  errors: readonly string[]; error: string | null; issues: readonly Issue[];
  valid: boolean; invalid: boolean; pending: boolean;
  touched: boolean; untouched: boolean; dirty: boolean; pristine: boolean;
  disabled: boolean; status: 'valid' | 'invalid' | 'pending' | 'disabled';
}
interface Issue { message: string; path: readonly (string | number)[] }
```

- `dirty` = value differs (deep) from the initial value. `touched` = an input of the control lost
  focus, or `touch()`/submit was called. A focus loss while a pointer is pressed inside the bound
  root takes effect after `pointerup`/`pointercancel` (next task, so after the `click`), so an error
  appearing can't shift the pressed button and lose the click.
- `pending` = a schema or async rule is running _or debouncing_. A pending control is neither
  `valid` nor `invalid`. A field's async rules share one debounce: the longest one declared.
- Disabled controls: no errors, `valid: true`, excluded from form validity and submitted output.
- Form `valid` = every enabled control valid and none pending.

#### Store contract

`form.subscribe(listener: (state) => void): () => void` — the listener is called **immediately**
with the current state and after every change. Compatible with `useSyncExternalStore` and the
Svelte store contract.

#### Commands

| Method                                          | Behaviour                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `setValue(name, value)` / `setValues(partial)`  | set + validate; mirrored into bound inputs                                                                                                                                                                                                                                                                       |
| `validate(): Promise<boolean>`                  | runs sync rules, flushes debounces, awaits schemas/async rules                                                                                                                                                                                                                                                   |
| `handleSubmit(onValid, onInvalid?)`             | returns `(event?) => Promise<void>`: `preventDefault`, ignore while `submitting`, `submitCount++`, touch all, `await validate()`; valid → `onValid(output, event)`; invalid → focus first invalid, `onInvalid(state, event)`. Errors thrown by handlers propagate (never swallowed); `submitting` always resets. |
| `reset(values?)`                                | optional new initial values; restores values, clears touched/dirty/submitCount, aborts async, re-validates, writes inputs                                                                                                                                                                                        |
| `touch(name?)` / `untouch(name?)`               | one control, or all when omitted                                                                                                                                                                                                                                                                                 |
| `disable(name)` / `enable(name)`                | mirrored to bound inputs' `disabled`                                                                                                                                                                                                                                                                             |
| `addFields(map)` / `removeFields(...names)`     | dynamic forms; re-adding a name replaces it                                                                                                                                                                                                                                                                      |
| `bind(target: Element \| string)` → `unbind` fn | see §4                                                                                                                                                                                                                                                                                                           |
| `unbind()`                                      | removes listeners and every attribute Formidate added                                                                                                                                                                                                                                                            |

### 3.4 Validation pipeline (per control)

1. **Sync**: DSL rules (+ HTML-inferred rules) → `sameAs` → `custom`. Re-run for every control on
   every change (cheap, keeps cross-field rules correct). Synchronous.
2. **Schema** (if any): re-run only when the value changed. Sync results apply immediately; a
   promise marks the control pending. Results are tagged with a run token — **a stale result is
   discarded**.
3. **Async rules**: only if 1–2 produced no issues and the value is non-empty; only when the value
   changed since the last async run; debounced; previous run aborted (`AbortController`).

`submit` and `validate()` flush debounces and await everything.

**SSR**: with no `document`, async rules are marked pending but not started (no requests or timers
during render; the snapshot matches the browser's first one). `validate()` starts them.

## 4. DOM binding

`bind(form | selector)` — any element works; a `<form>` additionally gets submit/reset handling.

- **Elements**: `form.elements` (includes `form="id"` associated controls) or `querySelectorAll`
  for non-form roots. Named `input`/`select`/`textarea`, excluding buttons.
- **Name**: `data-formidate-control` overrides `name`. Names are parsed like servers do (PHP,
  Rails, `qs`) so `values` matches the submitted payload: `a[b]`, `a[0][b]`, and dot notation
  `a.b` / `a.0.b` (mixable) create structure (an index mixed with a name, `a[0]` + `a[k]`, makes an object); `a[]` is a list — positional for text inputs and
  error slots (n-th input ↔ index n, blank → `null`), collected for checkboxes / `<select multiple>`.
  Malformed names are flat keys; `__proto__`/`constructor`/`prototype` segments are ignored.
- **Reading** (synchronous, on `input`/`change`): text → string (blank → `null`); single checkbox →
  `value` if checked else `null`; radio group → checked value; `<select multiple>` / several
  checkboxes in an `.array()` (or undeclared/nested) control → `string[]`.
- **Source of truth on bind**: if a control has an explicit default or was set programmatically,
  the value is **written** into the inputs; otherwise the inputs' current value is **read** and
  becomes the initial value. After that, user input flows in, and `setValue`/`reset` flow out.
- **`html: true`**: every named input not declared in the field map becomes a control, and
  constraint attributes become rules (`required`, `type=email|url|number|range|date|datetime-local`,
  `minlength`, `maxlength`, `min`, `max`, `step` on number inputs, `pattern`; `min`/`max` on
  `time`/`month`/`week` compare as strings with the `minDate`/`maxDate` messages, an overnight `time`
  range is not checked; unparsable limits are ignored) — unless the declared `Field` already has that
  rule kind (explicit wins; other kinds are added). Attribute rules apply **per input path**, so
  list rows and object members are validated individually with issues at their path, labelled by
  their own `<label>`/`aria-label`. Schema-backed controls are never augmented. Inputs disabled at
  bind time (incl. via `<fieldset disabled>`) start disabled; disabled inputs of a control that has
  enabled ones are left out (read, rules, errors), like `FormData`.
- **Dynamic DOM**: a `MutationObserver` on the root runs `refresh()` when inputs are added or
  removed: new inputs join/create controls, inferred controls without inputs are removed, declared
  ones become empty (`null` / `[]`). Code values are written into inputs only on first connect;
  afterwards the DOM is the source of truth. `refresh()` is public for attribute changes.
- **`novalidate`** is set on a bound `<form>` (restored on unbind) — Formidate owns the error UI,
  and keeps the native constraints via `html`.
- **Touched**: `focusout` from an input of the control. Visibility of errors (aria + slots) is
  tracked **per input element**, so a newly added list row stays quiet until left (and a removed
  row's state leaves with it); `touch()` and
  submit reveal everything.
- **Events** (`input`, `change`, `focusout`) are delegated from the root, plus direct listeners on
  `form="id"` controls outside it (re-read on `refresh()`). Nothing is attached to the document, so a
  root removed without `unbind()` is garbage-collected with its form.
- **Values set without events** (autofill, scripts, hidden inputs) are re-read by `validate()`,
  `handleSubmit()` and the submit gate.
- **Submit gate**: a native submit of an invalid/pending form is prevented and all controls
  touched; if invalid, the first invalid input is focused. If it was only pending, the gate awaits
  `validate()` and, if valid, calls `requestSubmit(submitter)` — unless `handleSubmit` ran for the
  same submit (`submitCount` changed), a later submit superseded it, or the form was unbound.
  Valid forms submit natively, untouched.
- **Reset**: a native `reset` event resets the form state after the browser resets the inputs.
- **`aria: true`** (on every change):
  - `aria-invalid="true"` on inputs of a control that is touched and has an issue whose path
    matches the input (whole-value issues match every input); removed otherwise.
  - `[data-formidate-error="name"]` elements (same name syntax as inputs) receive the first
    visible message (its input was left, or all after submit) whose path they are the **most
    specific slot** for, get `hidden` when empty (not for `aria-live`/`role` slots), get an unused
    `id` if missing, and that id is added to the matching inputs' `aria-describedby` (and removed
    again when the slot leaves). Slots added later are wired immediately.

## 5. React — `formidate/react`

```ts
const { ref, handleSubmit, controls, values, valid, form, ... } = useForm(fieldsOrForm, options?);
```

Creates the form once (or uses the given `Form`), subscribes with `useSyncExternalStore`, returns
the immutable snapshot spread together with `form`, `ref` (callback ref → `bind`/`unbind`) and a
stable `handleSubmit`. Peer: `react >= 18`.

## 6. Packaging & tooling

- **ESM-only** (`"type": "module"`, `exports` with `types` first), `sideEffects: false`.
  Node ≥ 20.19 can `require()` it. CDN: `dist/formidate.iife.js` (minified, `window.Formidate`).
- Build: **tsdown** with `isolatedDeclarations` (fast, TS-7-safe d.ts) and built-in
  **publint** + **arethetypeswrong** checks.
- Lint/format: **Biome** (one tool instead of ESLint + typescript-eslint + Prettier + 3 configs).
- Tests: **Vitest** + jsdom; React tested against 19 (CI also runs React 18).
- Size budget: **size-limit**.
- Releases: **Changesets** (pre-release mode `beta`) + GitHub Actions publishing with npm
  **trusted publishing / provenance** (OIDC, no `NPM_TOKEN`).
- CI: Node 22 & 24 — lint, typecheck, test+coverage, build (+ package lint), size.
